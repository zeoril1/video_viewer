# Загрузка, ресурсы и совместный просмотр

## Что доступно

- При запуске серии отображается поиск источника; при открытии потока — подключение и буферизация. После 20 секунд появляются действия повторного запуска и смены источника. Ожидание измеряется по фактическим событиям плеера, без выдуманного процента готовности. Блок работает и в полноэкранном режиме. Ограничение сервера возвращает HTTP 503 с `Retry-After`.
- В «Настройках просмотра» доступны размер, фон, положение и задержка текстовых субтитров от −30 до +30 секунд. Положительная задержка показывает текст позже. Язык сохраняется и выбирается при следующем запуске, если дорожка есть в файле. Настройки аккаунта хранятся в `personal_items`, без входа — только в памяти страницы. Растровые субтитры PGS/DVD не преобразуются в текст.
За пять минут до конца серии начинается загрузка следующего видеофайла целиком. Сначала проверяется текущая раздача, затем до трёх подходящих источников; требуется точное совпадение сезона и серии. Найденная раздача используется при переходе даже до завершения загрузки. Первые 8 МиБ читаются с упреждением 4 МиБ, остальной файл скачивается с обычным приоритетом, ниже активных читателей плеера. Остальные серии пакета не запрашиваются. До двух одновременных подготовок, до шести минут на запрос; кэш удерживается десять минут (при давлении на диск возможна выгрузка). ffmpeg заранее не запускается. Смена серии/источника, выход со страницы или выключение настройки отменяет загрузку, сохраняя уже полученные данные. Ошибки повторяются через 30 секунд при продолжающемся просмотре. Скорость переключения зависит от сидов, сети и запуска ffprobe/ffmpeg.
- Кнопка «Смотреть вместе» создаёт комнату и ссылку. Создатель — ведущий: его пауза, позиция, фильм и серия передаются участникам. Создание комнаты и подключение доступны без авторизации. Создатель видит список подключённых: имя аккаунта для вошедших пользователей и IP для гостей. Список доступен только создателю; выход удаляет участника сразу, при потере связи запись исчезает через 15 секунд. Отдельные вкладки/устройства учитываются отдельно, даже если IP совпадает. Озвучка, субтитры и качество остаются личными. Опрос выполняется раз в 1,5 секунды; расхождение больше трёх секунд корректируется, повторная перемотка — не чаще раза в восемь секунд. Это синхронизация домашнего просмотра, не покадровая синхронизация.

Комнаты хранятся в памяти сервиса `auth`: до трёх на аккаунт (без входа — на IP), до 128 комнат всего и до 128 подключений на комнату, срок жизни — 30 минут без обновлений ведущего. При потере связи с ведущим участники ставятся на паузу. Перезапуск `auth` закрывает комнаты; перезагрузка страницы ведущего не восстанавливает его управление — создайте новую комнату. Приглашение позволяет читать состояние, но не управлять им: изменения и список участников требуют отдельный секрет ведущего, который не включается в ссылку. Вход/выход из аккаунта не отнимает управление у создателя. IP поступает от шлюза; `X-Forwarded-For` принимается только от настроенного доверенного прокси `TRUSTED_PROXY`.

## Ограничения ресурсов

Параметры задаются в `.env`, примеры есть в `.env.example`:

| Переменная | По умолчанию | Значение |
|---|---:|---|
| `STREAM_MAX_SESSIONS` | 4 | Одновременно запущенные/запускаемые HLS-процессы ffmpeg |
| `STREAM_CACHE_BYTES` | 42949672960 | 40 ГиБ логического размера торрент-спула |
| `STREAM_HLS_BYTES` | 8589934592 | 8 ГиБ временных HLS-файлов |
| `STREAM_MIN_FREE_BYTES` | 2147483648 | Резерв свободного диска 2 ГиБ; 0 отключает резерв |
| `STREAM_MEMORY_LIMIT` | 2g | Лимит памяти контейнера stream |
| `STREAM_CPUS` | 4.0 | Лимит CPU контейнера stream |

Параллельно допускаются не более четырёх проб ffprobe. Контейнер ограничен 256 процессами/потоками. Настройки относятся к сервису `stream`; собственный лимит IPTV `IPTV_MAX_SESSIONS` остаётся независимым.

Квота спула резервируется **перед каждой записью**, совместно для всех файлов; перезапись существующего диапазона не расходует квоту повторно. Учитывается логический размер, включая пустые промежутки при перемотке. Поэтому разреженный файл может исчерпать квоту раньше фактического заполнения диска. При открытии торрента в условиях нехватки места удаляются неиспользуемые кешированные торренты; активные читатели не вытесняются. Если места всё равно нет, рост спула отклоняется, просмотр может потребовать повторного запуска после освобождения места.

Свободное место проверяется с интервалом до секунды. Объём HLS проверяется раз в секунду: ffmpeg пишет независимо, поэтому между проверками возможно превышение порога. При превышении HLS-квоты или исчерпании резерва HLS-процессы останавливаются и их файлы удаляются. Это аварийный предохранитель, а не дисковая квота файловой системы.

`stream-cache` и новый `stream-hls-cache` содержат временные данные. При старте процесса удаляются только узнаваемые файлы спула и каталоги HLS предыдущего запуска. **Эти тома принадлежат одному экземпляру stream**, их нельзя совместно монтировать в несколько работающих экземпляров. История просмотра и личные настройки остаются в PostgreSQL.

Для запуска без Compose используются флаги `-max-sessions`, `-cache-bytes`, `-hls-bytes`, `-min-free-bytes`. `HLS_WORK_ROOT` задаёт отдельный каталог HLS с очисткой предыдущего запуска; не указывайте общий каталог другой работающей копии сервиса.

## Обновление и проверки

Из каталога `video_viewer`:

```sh
docker compose up -d --build
go test ./...
node --test tests/*.test.cjs
node tests/playback.browser.cjs
```

Браузерный тест использует Playwright/Chromium и локальные HTTP/media-фикстуры. При необходимости задайте `PLAYWRIGHT_MODULE` и `CHROMIUM_PATH`; `PLAYBACK_SCREENSHOT` задаёт путь скриншота. Проверяются загрузка, настройки и временные метки субтитров, подготовка серии, две страницы совместного просмотра, пауза/перемотка/продолжение, закрытие комнаты и мобильная ширина. Тест не проверяет доступность внешних раздач. Серверные тесты отдельно проверяют права на комнаты, срок жизни, лимиты, конкурентное резервирование диска и возврат слота после ошибки запуска.
