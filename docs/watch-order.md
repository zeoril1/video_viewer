# Автоматический порядок просмотра

На странице фильма/сериала блок «Порядок просмотра» загружается независимо от плеера и доступен без входа. Он показывает текущую часть, отметки просмотренных произведений из аккаунта и переходы в каталог. Для неподтверждённых совпадений есть кнопка поиска. Если связанных частей нет, блок скрывается; при ошибке можно повторить запрос.

Источники:

- TMDB: состав киноколлекции, отсортированный по дате выхода.
- MCU: метка `marvel cinematic universe (mcu)` в TMDB объединяет фильмы и сериалы. Сериалы расположены по дате премьеры первого сезона. Покрытие зависит от полноты меток провайдера; это не официальный полный список Marvel.
- AniList: точное совпадение названия, года и формата для анимации, затем обход PREQUEL, SEQUEL, SIDE_STORY, PARENT, SUMMARY. Манга, альтернативные экранизации и связи ADAPTATION не включаются. До 64 произведений, до 12 пакетных запросов после поиска; ограниченный результат помечается как неполный. OVA, SPECIAL и побочные/сводные части отмечаются отдельно. Порядок — по дате выхода, а не гарантированная сюжетная хронология; дата может быть неполной.

Произведения с TMDB ID открываются даже при отсутствии в локальной базе. Для аниме совпадение с локальным каталогом требует анимационного жанра, точного названия и года. Сезоны, существующие только как часть одной карточки сериала, могут оставаться без отдельной ссылки: автоматического сопоставления AniList-сезона с номером сезона TMDB пока нет. Неоднозначные совпадения требуют выбора пользователем в поиске.

`GET /api/films/{id}/watch-order` принимает IMDb ID или `tmdb-movie-N`/`tmdb-tv-N`. Требуется существующая настройка TMDB; отдельный ключ AniList не нужен. Каталог должен иметь сетевой доступ к `graphql.anilist.co` и TMDB.

Таблица `watch_orders` создаётся при запуске catalog. Результат хранится 24 часа, после чего обновляется при следующем обращении. Старая успешная версия сохраняется при ошибке провайдера. Без PostgreSQL используется ограниченный кэш в памяти на 256 записей. Два запроса к источникам одновременно, одинаковые запросы объединяются; AniList вызывается не чаще раза в 2,1 секунды. Новые данные проверяются при открытии карточки; отдельного фонового сканирования каталога нет.

Применение: `docker compose up -d --build catalog gateway`, затем обновить страницу. Плеер и stream менять не требуется.

Проверки: `go test ./internal/catalogapi ./internal/tmdb ./internal/db ./internal/gatewayapi`. Проверка сохранения в PostgreSQL требует `TEST_DATABASE_URL` и использует временную таблицу. Браузерная проверка: `node tests/watch_order.browser.cjs` с Playwright, Chromium и доступной директорией `/output`.

Документация источников: https://developer.themoviedb.org/reference/collection-details и https://docs.anilist.co/reference/enum/mediarelation.
