# Уведомления о подписках в Telegram

В медиатеке можно подключить Telegram к своему аккаунту. Подписываться можно на фильмы и сериалы. Сервис `auth` проверяет подписки каждые **6 часов**, даже когда сайт закрыт.

## Что приходит

- Фильм появился в доступных раздачах.
- В раздаче найдены файлы новых серий. Даты премьеры или эфира без источника недостаточно для уведомления.
- Для уже известного фильма или серии появилось лучшее качество: например, TS → WEB → BD/BR. Внутри одного формата учитывается повышение разрешения.
- Появилась другая озвучка, даже если её качество ниже уже известного варианта.

В сообщении указаны произведение, сезон и номера серий, озвучка, формат, разрешение и ссылка на карточку сайта. Несколько серий одного варианта объединяются; длинные обновления разбиваются на сообщения.

Озвучка и качество берутся из описаний раздач и имён файлов, без скачивания видео и запуска FFmpeg. Это заявленные параметры, а не результат проверки звуковых дорожек. Неуказанные сведения обозначаются прямо. Смешанное качество пака, например «BDRip, WEB-DL», не приписывается всем сериям: без уточнения в имени файла формат остаётся неизвестным. Наличие метаданных раздачи не гарантирует доступность всех пиров во время будущего просмотра.

Порядок форматов для уведомлений: CAM < TS < TC < SCR < DVD < HDTV < WEB < BD/BR. Формат важнее разрешения: WEB 720p после TS 1080p считается обновлением. Появление менее приоритетного формата для той же озвучки не вызывает уведомления. Качество разных озвучек сравнивается отдельно.

При первой проверке существующего сериала приходит только последняя доступная серия с найденными вариантами; остальные серии запоминаются без рассылки старого каталога. Для фильма отправляется одно уведомление о доступных вариантах. Последующие проверки учитывают новые серии, озвучки и улучшения качества уже известных серий.

## Настройка сервера

1. Создайте отдельного бота через [BotFather](https://core.telegram.org/bots/tutorial#obtain-your-bot-token).
2. В `.env` задайте:

   ```dotenv
   TELEGRAM_BOT_TOKEN=токен_бота
   NOTIFICATIONS_PUBLIC_URL=https://kino.zeoril.ru
   ```

3. Обновите сервисы:

   ```sh
   docker compose up -d --build --no-deps auth catalog stream gateway
   ```

Новые таблицы создаются при запуске через `EnsureSchema`. Пустой `TELEGRAM_BOT_TOKEN` отключает обработчик Telegram и показывает в медиатеке, что бот ещё не настроен. Токен хранится на сервере, не передаётся браузеру и не включается в сообщения об ошибках.

Бот использует [getUpdates](https://core.telegram.org/bots/api#getupdates), поэтому этот же токен не должен одновременно обслуживаться другим приложением или webhook. Приложение не удаляет существующий webhook автоматически. Наружный URL для входящих запросов Telegram не требуется: достаточно исходящего HTTPS из `auth` к `api.telegram.org`.

При запуске без Compose задайте также `NOTIFICATIONS_CATALOG_URL` и `NOTIFICATIONS_STREAM_URL`. По умолчанию используются `http://catalog:8081` и `http://stream:8082`. Это внутренние адреса сервисов. Период проверки фиксирован на шести часах; отдельный cron не нужен.

## Подключение пользователя

1. Войти на сайт и открыть **Моя медиатека → Уведомления в Telegram**.
2. Нажать **Подключить Telegram**, затем **Открыть бота в Telegram** и **Запустить**.
3. Вернуться на сайт и нажать **Я подключил — проверить**.
4. На страницах нужных фильмов и сериалов нажать **Подписаться**.

Привязка использует одноразовую [ссылку запуска бота](https://core.telegram.org/bots/features#deep-linking), действующую 10 минут. Она работает только в личном чате владельца Telegram. Другой аккаунт сайта не может забрать уже привязанный чат; сначала нужно отключить прежнюю привязку.

В медиатеке можно приостановить, возобновить или отключить Telegram. Команда `/stop` в боте приостанавливает уведомления. Пауза, отключение и отписка отменяют ожидающие сообщения; уже отправляемый запрос может успеть завершиться. После паузы старые отменённые уведомления не рассылаются заново.

## Повторные проверки и ошибки

- История вариантов, очередь доставки, позиция чтения Telegram и время последней проверки хранятся в PostgreSQL. Перезапуск не запускает повторную рассылку уже учтённых вариантов и не сбрасывает шестичасовой интервал.
- Изменение magnet, адресов трекеров, числа сидов или порядка результатов не создаёт новое событие. Проверяются все найденные раздачи, включая пак с тем же magnet, в котором добавились файлы серий.
- Поиск одного произведения общий для всех его подписчиков. У каждого пользователя своя история и очередь. При ошибках отдельных источников учитываются подтверждённые файлы; если источники вообще не удалось проверить, состояние не заменяется пустым результатом.
- Источники проверяются по полному названию произведения, поэтому общее слово франшизы не создаёт уведомления о другом сериале. Пустая выдача отдельного трекера кешируется не дольше 6 часов и может быть перепроверена в следующем цикле.
- Временная ошибка Telegram оставляет уведомление в очереди. Повторы идут с увеличением задержки до часа. HTTP 429 приостанавливает отправку до указанного Telegram срока, включая остальные сообщения; запрет бота пользователем отключает привязку для доставки.
- Блокировка PostgreSQL разрешает работать только одному обработчику Telegram, даже если запущено несколько экземпляров `auth`. Потеря соединения с блокировкой останавливает его работу.

Сохранение нового состояния и добавление уведомлений в очередь — одна транзакция. Как и для обычной HTTP-доставки, редкий обрыв между успешной отправкой Telegram и записью подтверждения в БД может привести к повтору сообщения: Bot API не предоставляет ключ идемпотентности для `sendMessage`.

## Проверки

```sh
go test ./internal/releasewatch ./internal/authapi ./internal/gatewayapi ./internal/db
node --test tests/*.test.cjs
node tests/telegram_notifications.browser.cjs
```

Для транзакционных проверок задайте `FEATURE_TEST_DATABASE_URL` отдельной тестовой PostgreSQL. Тесты создают и удаляют собственные случайные схемы. Выполняйте пакеты последовательно (`go test -p 1 ...`), поскольку тест единственного обработчика намеренно использует общую блокировку БД. Не используйте рабочую базу. Telegram в тестах заменён локальными ответами; реальные сообщения не отправляются.
