# 🎬 Video Viewer

Веб-каталог видео, которые **стримятся по торрент-магнет-ссылкам**.
Файлы **не хранятся на сервере**: данные качаются в оперативную память
и сразу отдаются плееру через HTTP (с поддержкой Range-запросов).

- **Бэкенд:** Go ([anacrolix/torrent](https://github.com/anacrolix/torrent) — in-memory хранилище, без записи на диск)
- **Каталог:** PostgreSQL + IMDb (топ-250, популярные, поиск)
- **Фронтенд:** ванильные HTML/CSS/JS, без сборки
- **Стриминг:** `Range` + `Accept-Ranges: bytes`, настраиваемый readahead

## Как это работает

Проект разбит на **микросервисы** (монorepo, общий Go-модуль): браузер
ходит только на API-шлюз **gateway**, который раздаёт статику `web/` и
проксирует `/api/*` на внутренние сервисы.

```
┌────────────┐  /api/* (web)  ┌──────────┐
│  Браузер   │ ─────────────▶ │ gateway  │  :8080
│ (каталог,  │                └──────────┘
│  плеер)    │                     │
└────────────┘                     │ reverse-proxy /api/*
                                   ▼
      ┌───────────────┬──────────────────┬───────────────┐
      │   catalog     │      stream      │     auth      │
      │    :8081      │      :8082       │     :8083     │
      │ IMDb/TMDB/    │  торрент-клиент  │  авторизация  │
      │ Jackett, БД   │  стрим + HLS     │  + история    │
      └───────────────┴──────────────────┴───────────────┘
```

- **gateway** (`cmd/gateway`, `:8080`) — статика `web/` + reverse-proxy
  `/api/*` на сервисы; агрегирует `/api/health`.
- **catalog** (`cmd/catalog`, `:8081`) — каталог (IMDb + TMDB + локальные
  магнеты), детали фильмов, поиск источников через Jackett. **Владеет
  PostgreSQL** (таблицы `films`, `sources`).
- **stream** (`cmd/stream`, `:8082`) — торрент-клиент (in-memory),
  Range-стриминг, файлы торрента, HLS-транскодинг (ffmpeg).
- **auth** (`cmd/auth`, `:8083`) — авторизация (сессии) и история просмотра.

Внутренние сервисы не публикуют порты наружу; наружу выставлены только
gateway `:8080` (HTTP) и `42069/udp` (торрент-порт stream).

1. Браузер получает каталог из `GET /api/catalog` (JSON из `data/catalog.json`).
2. При клике на карточку плеер открывает `GET /api/stream/{id}`.
3. stream добавляет магнет-ссылку в торрент-клиент, ждёт метаданные
   и читает данные в память (без записи на диск), отдавая их плееру
   порциями по мере скачивания.
4. Если торрент содержит несколько файлов, для стриминга автоматически
   выбирается самый крупный видеофайл (по расширению: `.mp4`, `.mkv`,
   `.webm`, `.avi` и др.). Если видеофайлов нет — берётся самый большой
   файл.

## Быстрый старт (локально, без Docker)

```bash
go mod tidy
go run . gateway     # API-шлюз (web + прокси /api/*) — http://localhost:8080
go run . catalog     # каталог (в отдельном терминале)
go run . stream      # стриминг (в отдельном терминале)
go run . auth        # авторизация и история (в отдельном терминале)
```

`go run . <сервис>` — диспетчер, запускающий нужный сервис из `cmd/`
(без аргумента выводит список). Порты по умолчанию: gateway `:8080`,
catalog `:8081`, stream `:8082`, auth `:8083`. Откройте
http://localhost:8080

### Docker Compose

```bash
docker compose up -d --build
```

Compose поднимет **6 сервисов**: `db` (PostgreSQL), `jackett`, `catalog`,
`stream`, `auth` и `gateway`. Веб-интерфейс — http://localhost:8080.
Внутренние порты сервисов (`:8081`/`:8082`/`:8083`) наружу не публикуются.

## Источники для просмотра (on-demand)

При открытии фильма сервер делает **живой запрос к Jackett** (Torznab
API, `GET /api/films/{id}/sources`) и возвращает доступные варианты
раздач. Сервер **парсит из заголовка раздачи качество**
(`2160/1080/720/480`, `4K/UHD`) и **озвучку**
(`dub`/`multi`/`two`/`single`/`original`/`subs`) и **ранжирует**
варианты: озвучка > качество > число сидов. Фронтенд группирует
источники **«озвучка → качество»** (чипы озвучек из всех раздач, внутри
— чипы качества) и автоматически запускает лучший (первая озвучка,
максимальное качество). Пользователь может выбрать другую озвучку,
качество или конкретную раздачу.

**Весь поиск источников идёт через Jackett** — это единственный
провайдер (`magnet.Provider`, реализация `internal/magnet/jackett.go`).
Запрос строится по названию фильма **с переводом** — «Русское / English
год» (например, «Одержимость / Whiplash 2014»), так как раздачи на
трекерах названы аналогично. Такой запрос точно идентифицирует фильм и
не цепляет одноимённые (напр. корейский «Одержимость / Inganjungdok» —
не Whiplash). Если перевода нет — берётся одно доступное название
(`trackerTitle` в `sources.go`).

Jackett отдаёт magnet-ссылки (если в индексере включён
«UseMagnetLinks») или `.torrent` (тогда сервис скачивает `.torrent` и
извлекает из него info hash, строя magnet). Результаты Jackett
помечаются провайдером `jackett`.

### Поиск через Jackett (единственный способ)

**RuTracker.org закрыт Cloudflare** (JS-челлендж): прямой запрос из
сервиса даёт `403`, а ввод капчи не помогает — сайт не отдаёт страницу
входа не-браузерным клиентам. Jackett сам хранит доступы, решает капчу
при настройке и обходит Cloudflare — поэтому все запросы к трекерам
идут только через него.

Jackett поднимается **вместе с сайтом** (сервис `jackett` в
`docker-compose.yml`, веб-интерфейс `http://localhost:9117`, конфиг в
`./jackett/`). Остаётся сделать вручную:

1. Откройте веб-интерфейс Jackett (`http://localhost:9117`) и добавьте
   индексер **RuTracker.org** (Type: semi-private) — введите логин/пароль
   и пройдите капчу (это делает сам Jackett).
2. Укажите API-ключ Jackett в `.env`:
   `JACKETT_API_KEY=<ключ>` — он лежит в `./jackett/Jackett/ServerConfig.json`
   (поле `"APIKey"`) или виден на вкладке Dashboard веб-интерфейса.
3. Перезапустите `docker compose up -d` — в логах `video-viewer-catalog`
   появится `jackett: http://jackett:9117 indexer=rutracker-ru`.

`JACKETT_URL` по умолчанию уже указывает на сервис compose
(`http://jackett:9117`); `JACKETT_INDEXER` — ID индексера (по умолчанию
`rutracker-ru` — имя файла в `./jackett/Jackett/Indexers/`, или `all` для
всех настроенных). **Важно:** если ID не совпадает с реальным именем
индексера в Jackett, Jackett отвечает `Indexer is not configured` —
поиск ничего не найдёт. Переменные задаются в `.env` (см. `.env.example`).
Без `JACKETT_URL` поиск источников отключён (сервис стартует с
предупреждением).

### Фоновый поиск источников

Поиск на трекере — **асинхронный, в фоне** (`internal/catalogapi/sources_bg.go`):
`GET /api/films/{id}/sources` **не блокирует** пользователя медленным Jackett.
Первый ответ приходит мгновенно (из кэша БД) со статусом `"ready"` либо
`"searching"`; при статусе `"searching"` фронтенд опрашивает endpoint
каждые ~4 секунды, пока фоновое задание не сохранит результат в БД
(максимум 3 минуты, до 3 поисков одновременно). Пока идёт поиск,
интерфейс показывает обратный отсчёт — страница и плеер остаются
отзывчивыми. Свежие результаты кэшируются на 20 минут (повторный поиск
при быстром переоткрытии не запускается). Всё то же ранжирование
«сезон → озвучка → качество → сиды» применяется и к кэшированным
вариантам (`sortSourceItems` / `sourceItemsFromDB`).

### Таблица `sources` (магнет-ссылки и метаданные)

Все найденные раздачи (и из on-demand `/sources`, и из фонового поиска
магнетов) сохраняются в PostgreSQL в таблице **`sources`**
(`internal/db/sources.go`): `film_id`, `info_hash`, `magnet`, `title`,
`size`, `seeds`, `quality`, `audio`, `season`, `provider`, `checked_at`,
`created_at`, `updated_at`.

- **Ключ записи — `info_hash`** (хеш из `xt=urn:btih:...`), а не строка
  магнита: трекер отдаёт магниты с разными сессионными токенами, поэтому
  сравнение по строке магнита плодило бы дубли при каждом поиске.
- **Upsert по разнице** (`SaveSources`): новые релизы вставляются,
  существующие обновляются **только если изменились метаданные**
  (размер/сиды/качество/озвучка/сезон/провайдер); при отсутствии
  изменений обновляются лишь `magnet` (свежие трекеры) и `checked_at`.
  Источники, которых больше нет в свежей выдаче, удаляются. Возвращает
  число добавленных/обновлённых/удалённых (логируется в `sources: save`).
- Парсер метаданных общий для всех источников: `internal/magnet/parse.go`
  (`ParseTitle` → качество/озвучка/сезон).

> **Важно.** RuTracker и другие трекеры могут быть закрыты
> Cloudflare/антиботом или ограничивать скачивание. Список рабочих
> трекеров зависит от доступности из сети, где запущен сервер. Jackett
> берёт на себя обход антибота и капчу.

## Прокси для IMDb

Пакет `internal/proxy` реализует пул HTTP-прокси из статических адресов
(`PROXY_STATIC`) с failover: при сбое соединения прокси помечается
нерабочим, и запрос повторяется через следующий (до `-proxy-max-attempts`
раз) либо идёт напрямую, если рабочих прокси нет. Динамические публичные
списки (`PROXY_SOURCES`) не используются. Прокси применяются только к
запросам клиента IMDb (`internal/imdb/client.go`); запросы к Jackett идут
напрямую (он обычно локальный), P2P-трафик торрент-клиента не
проксируется.

Пример запуска со статическими прокси:

```sh
go run . -proxy-static "127.0.0.1:3128,http://user:pass@10.0.0.5:8080"
```

Логика: при сбое соединения прокси помечается нерабочим и запрос
повторяется через следующий (до `-proxy-max-attempts` раз). Если рабочих
прокси нет — запросы идут напрямую.

## Сериалы: сезоны и серии

Сериалы — это отдельные видеофайлы (серии) в торренте, часто сгруппированные
по сезонам. Поддержка:

- **Источники группируются по сезону** (`internal/catalogapi/sources.go`):
  из заголовка раздачи парсится сезон (`S01`/`сезон N`/`season N`), в UI
  над озвучкой/качеством появляются чипы сезонов (раздачи без сезона —
  «Полный» — идут последними).
- **Выбор серии** (`internal/streamapi/episodes.go`): `GET
  /api/films/{id}/files?magnet=...` открывает торрент, перечисляет
  видеофайлы и определяет сезон/серию из имени (`SxxExx`, «сезон N»,
  «серия N», номер в конце имени). Фронтенд показывает селектор
  «Серии» (чипы сезонов + сетка серий); клик запускает выбранную серию.
- **Стрим конкретного файла**: параметр `file` (индекс в торренте)
  пробрасывается через `/api/stream/{id}`, `/api/films/{id}/tracks` и
  `/api/films/{id}/hls.m3u8` — ffmpeg читает именно выбранную серию.

## Звук и выбор дорожек (HLS через ffmpeg)

В торрентах звук часто в кодеках, которые браузер не декодирует
(AC3/DTS/EAC3) — поэтому при прямом стриминге «нет звука». Чтобы это
исправить, видео воспроизводится через **HLS**: ffmpeg копирует видео
как есть (`-c:v copy`) и **перекодирует звук в AAC** (`-c:a aac`),
фронтенд играет поток через [hls.js](web/vendor/hls.min.js).

- `GET /api/films/{id}/tracks` — список звуковых дорожек (ffprobe):
  **глобальный индекс потока**, кодек, язык, название + **полная
  длительность** (`duration`, сек). Индекс дорожки — глобальный номер
  потока в контейнере (у MKV аудио обычно с индексов 1..N), он же
  передаётся в ffmpeg как `-map 0:N` — поэтому выбор любой дорожки
  корректен, даже если аудио-потоки не начинаются с нуля.
- `GET /api/films/{id}/hls.m3u8?magnet=...&track=N&start=S&quality=Q` —
  запускает ffmpeg для выбранной дорожки и отдаёт плейлист (сегменты —
  абсолютные URL). `start` — позиция в секундах (перемотка: ffmpeg стартует
  с неё через `-ss`); `quality` — серверное понижение качества
  (`source|2160|1080|720|480`: ffmpeg перекодирует видео в H.264 с
  ограничением высоты кадра, не выше исходной).
- В модалке, если дорожек несколько, показывается селектор — клик
  перезапускает поток с выбранной дорожкой (позиция и качество сохраняются).

### Плеер: полная длительность и полоса «переданного»

HLS из ffmpeg прогрессивный (без `#EXT-X-ENDLIST`), поэтому браузер
считает его «live» и `video.duration` равен `Infinity` — полная
длительность через нативные контролы не видна. Поэтому у плеера
**свои контролы**:

- Полная длительность берётся из `GET /api/films/{id}/tracks`
  (`duration`, вычисляется ffprobe из метаданных торрента) и
  отображается всегда: `текущее / полное` и полная шкала.
- Часть, которая уже передана/загружена (`video.buffered`), показывается
  отдельной полупрозрачной полоской внутри шкалы.
- Перемотка кликом по шкале — в любое место полной длительности. В уже
  переданную часть — обычный seek; в **непереданную** (например, сразу
  в середину после старта) — сервер перезапускает ffmpeg с этой позиции
  (`start=S`), поэтому мотнуть в середину можно даже в самом начале
  просмотра.
- Кнопки: play/pause, mute + громкость, полноэкранный режим.
- **Качество**: кнопки `SRC / 4K / 1080 / 720 / 480` — серверное
  понижение качества прямо в плеере (ffmpeg перекодирует; позиция и
  дорожка сохраняются). Автоматически выбирается максимальное качество
  лучшего источника, ниже можно уменьшить под канал/монитор.

Требуется **ffmpeg/ffprobe** в образе (добавлен в `Dockerfile`). Если
ffmpeg недоступен, фронтенд откатывается на прямой стрим без
транскодинга.

> **Медленный старт.** Торрент-стриминг запускается не мгновенно: ffmpeg
> ждёт пиров, метаданные и первые куски, поэтому плейлист и первые
> сегменты появляются с задержкой (иногда десятки секунд). На фронтенде
> для hls.js увеличены таймауты загрузки манифеста/уровней/сегментов
> (`manifestLoadingTimeOut` и т.д.), чтобы не было `manifestLoadTimeOut`
> при медленном старте. Сервер ждёт плейлист до 100 с; если ffmpeg упал
> раньше (нет пиров, битый файл) — сразу возвращает `502`, а не ждёт
> таймаут (в логах: `hls: ffmpeg ... завершился до плейлиста`).


> **Звук.** ffmpeg перекодирует звук в **AAC**, поэтому работает и там,
> где в исходнике AC3/DTS (их браузер не декодирует). Сегменты HLS —
> **fragmented MP4** (`init.mp4` + `*.m4s`): так hls.js/MSE воспроизводит
> и **HEVC (H.265)** видео (при поддержке кодекa браузером).
>
> **Автофолбэк H.265 → H.264.** Chrome/Firefox не декодируют HEVC через
> MSE (`bufferAppendError`). Если видео в H.265/HEVC, плеер **автоматически
> переключается на перекодирование в H.264 (1080p)**: `/api/films/{id}/tracks`
> отдаёт кодек видео (`codec`, `height`), и при HEVC поток стартует с
> качеством `1080` (серверный ffmpeg → libx264); при `mediaError`/
> `bufferAppendError` в исходном качестве срабатывает такой же фолбэк
> (один раз на источник). Пользователь видит уведомление «перекодируем
> в H.264», а из селектора качества может выбрать 4K/1080/720/480 —
> любое из них тоже транскодируется в H.264.

## Память

Торренты стримятся в память (in-memory хранилище, без записи на диск),
поэтому скачанные данные занимают RAM. Чтобы память освобождалась:

- **Ленивая аллокация кусков** — буферы выделяются только по мере
  скачивания, а не на весь объём торрента при открытии (открытие
  даже 10-ГБ фильма не раздувает память до его размера).
- При **закрытии плеера** фронтенд зовёт `GET /api/films/{id}/hls/stop` —
  ffmpeg останавливается, чтение торрента завершается.
- Когда у торрента **нет активных читателей** (никто не смотрит), он
  выгружается из клиента через `DropGrace` (по умолчанию 90 секунд) —
  освобождаются все скачанные данные, даже если досмотрели только часть.
- После выгрузки вызываются `runtime.GC()` + `debug.FreeOSMemory()`, чтобы
  Go вернул память операционной системе.
- Простаивающие ffmpeg-сессии HLS останавливаются автоматически (без
  запросов ~90 секунд).

Если фильм снова открывают в течение `DropGrace`, торрент не перекачивается
заново — выгруз отменяется, используется уже открытый экземпляр.

Диагностика памяти: `GET /api/debug/mem` (heap Go, открытые торренты,
активные HLS-сессии).

## Логирование и диагностика воспроизведения

Если фильм не воспроизводится, логи помогут понять причину. Смотрите
логи приложения: `docker compose logs -f video-viewer`.

- **Каждый HTTP-запрос** логируется с методом, путём, статусом и временем
  обработки (`http GET /api/films/tt0910970/hls.m3u8 -> 200 (2s)`).
- **Стрим**: открытие торрента, получение метаданных (число файлов),
  выбранный видеофайл и его размер.
- **ffprobe** (`/tracks`): число звуковых дорожек, длительность, ошибки
  (в т.ч. stderr ffprobe).
- **ffmpeg** (`/hls.m3u8`): полная командная строка, старт/остановка
  сессий, готовность плейлиста и время ожидания, таймаут плейлиста.
- **Сегменты HLS**: первый отданный сегмент на сессию и 404 «сессия не
  найдена» (обычно значит, что ffmpeg уже остановили или сессия протухла).
- **stderr ffmpeg** пишется в лог с префиксом `ffmpeg: ...` — там видно
  ошибки декодирования/контейнера.

На фронтенде доступна панель логов плеера:
- кнопка **🛠** в контролах плеера показывает/скрывает панель;
- панель содержит события hls.js (манифест, фрагменты, ошибки), результаты
  `/sources` и `/tracks`, ошибки запросов;
- при фатальной ошибке воспроизведения панель открывается автоматически;
- панель также включается параметром `?debug` в URL;
- те же строки дублируются в консоль браузера (DevTools → Console).

## Каталог из IMDb

Сервис умеет наполнять каталог фильмами из IMDb и хранить их в PostgreSQL.

- **Топ-250 и «популярные сейчас»** загружаются при старте и далее
  каждые **24 часа** (`-imdb-interval`). Новые фильмы вставляются в БД,
  существующие — обновляются (рейтинг, постер, позиция в чарте).
- **On-demand:** если пользователь открывает фильм, которого нет в БД
  (поиск в интерфейсе или `GET /api/films/{id}`), данные запрашиваются
  у IMDb и сохраняются в БД.

### Локализация (RU / EN)

В интерфейсе есть переключатель языка (кнопки `RU`/`EN`, выбор
запоминается в браузере). Названия и описания фильмов **хранятся в БД
на обоих языках** и показываются в зависимости от выбранного языка:

- английские название и описание — из IMDb (страница фильма) либо
  английской Википедии (`title`, `plot`);
- русские — метка и статья в русской Википедии через Wikidata
  (`title_ru`, `plot_ru`).

Заполнение русских данных происходит **фоном** (`internal/sync/localize.go`):
названия — пакетно через Wikidata Query Service (SPARQL, один запрос на
сотни фильмов), описания — из статей русской Википедии по сохранённым
заголовкам (`ruwiki_title`). Всё сохраняется в PostgreSQL; синхронизация
чартов не затирает русские значения (`NULLIF` + `COALESCE`).

Если перевода нет, показывается английский вариант (фолбэк).

Параметры: `-localize-workers` (параллельность описаний), `-localize-interval`.

### Источники данных IMDb

Прямой доступ к `www.imdb.com` может быть заблокирован (антибот-ответ `202`).
Поэтому для чартов используется схема с фолбэком:

1. Официальный скрапер IMDb (парсинг JSON-LD со страниц чартов)
   — работает там, где IMDb доступен;
2. Зеркало в формате JSON — по умолчанию топ-250 берётся из
   проверенного зеркала `movie-monk-b0t/top250`; для «популярных»
   зеркало можно указать через `-imdb-popular-url` (или `IMDB_POPULAR_URL`),
   если скрапер недоступен.

Поиск и получение по IMDb ID работают через собственный JSON-эндпоинт
автодополнения IMDb (`v2.sg.media-imdb.com`), он не требует ключа.

> Примечание: фильмы из IMDb не содержат магнет-ссылок — для них
> доступен детальный просмотр (постер, год, рейтинг, жанры), а стриминг
> появится после привязки магнет-ссылки.

## TMDB и Wikidata (вместо Кинопоиска)

Кинопоиск **отключён**: его публичный API работает под токеном с
ограничениями (`KINOPOISK_API_KEY`), а сайт `kinopoisk.ru` закрыт
антиботом. Его функции заменены двумя бесплатными источниками:

- **TMDB** (The Movie Database, `api.themoviedb.org/v3`) — свободный ключ
  без жёстких суточных лимитов (мягкий потолок ~40 req/s). Отвечает за
  **«популярные»** (`/movie/popular`), **«топ-250»** (`/movie/top_rated`)
  и **внешний поиск** (`/search/movie`). Включается ключами в env
  `TMDB_API_KEY` (API Key, v3) и/или `TMDB_ACCESS_TOKEN` (API Read Access
  Token, Bearer — приоритетный; в compose — через `.env`, ключи
  бесплатные на https://www.themoviedb.org/settings/api). Без ключей
  TMDB отключается — остаются IMDb-чарты и IMDb-поиск.
- **Wikidata** (WDQS SPARQL) — вообще без ключей. Отвечает за
  **обогащение карточек**: длительность, страна, режиссёр, главные роли
  (по IMDb-ссылке через свойство `P345`). Уже используется для
  локализации и числа сезонов.

Особенности реализации:

- **Чарты TMDB** синхронизируются при старте и далее каждые **24 часа**
  (тот же `-imdb-interval`): `sync.NewTMDBChart` → `tmdb.Popular` /
  `tmdb.TopRated` → `db.UpsertTMDBFilms` (колонки `rank_tmdb_popular`,
  `rank_tmdb_top250`). «Популярное» = IMDb moviemeter + TMDB popular.
- **Дедупликация с IMDb** — по `imdb_id`: TMDB-клиент дозаполняет ссылки
  через `/movie/{id}/external_ids` (параллельно, 6 потоков). Записи без
  IMDb-ссылки в каталог не добавляются.
- **Русские названия и описания** — TMDB отдаёт `title`/`overview` при
  `language=ru-RU`; жанры маппятся на имена в стиле IMDb (`878`→`Sci-Fi`).
- **Обогащение карточек из Wikidata** (`internal/wikidata`): один SPARQL
  на фильм, кэшируется в БД (`UpdateFilmExtras`); повторное открытие не
  ходит в сеть. Длительность `P2047` без единицы — минуты, с единицей
  «секунда» — делится на 60.
- Устаревшие Кинопоисковые колонки (`kinopoisk_id`, `rating_kp`,
  `votes_kp`, `rank_kp_top250`, `rank_kp_popular`), а также legacy
  `magnet` / `magnet_checked_at` и `year` **удалены** из таблицы `films`
  (2026-08-31): год вычисляется из `release_date`, магнеты фильмов живут
  в таблице `sources`. Для карточки рейтинг берётся: IMDb → TMDB.
- **Поиск по переводу и году**: запрос разбивается на слова, и запись
  совпадает, если все слова встречаются в русском/английском названии,
  категории, IMDb-ссылке или годе. Поэтому работает «Одержимость /
  Whiplash 2014» и «whiplash 2014». Для внешнего поиска из запроса
  берётся часть до «/» без года (`cleanSearchQuery`).
- **Поиск и вкладки**: секция передаётся вместе с запросом — вкладки
  фильтруют результаты поиска по разделу (при вводе запроса активна
  вкладка «Все», дальше можно переключиться на «Фильмы»/«Сериалы»/…).
  Внешние (on-demand) результаты тоже фильтруются по разделу и жанру.

Провайдеры: `internal/tmdb/` (клиент, поиск, чарты), `internal/wikidata/`
(SPARQL-обогащение). Пакет `internal/kinopoisk/` удалён.

### Карточка фильма: длительность, страна, режиссёр, актёры

Сервер **обогащает фильмы** данными из Wikidata (on-demand, один запрос
на фильм, результат кэшируется в БД):

- длительность (`movie_length`), страна выпуска (`countries`),
  режиссёр (`director`) и до 6 главных актёров (`actors`) — колонки `films`;
- поиск записи — по IMDb-ссылке (`P345`), это основной ключ каталога;
- повторное открытие не ходит в сеть: если поля уже заполнены — данные
  отдаются из БД.

**Маленькая карточка** в сетке каталога показывает до 5 строк:
**1)** название + рейтинг `★ 8.1/7.1` (IMDb/Кинопоиск/TMDB; если один
рейтинг — с меткой); **2)** название на другом языке · год · длительность
(`1 ч 48 мин`); **3)** страны · жанры; **4)** режиссёр; **5)** главные
роли; ниже — бейджи (сезоны, магнет, размер). Пустые строки скрываются.
`/api/catalog` отдаёт обогащённые поля (`movie_length`, `countries`,
`director`, `actors`, `rating_tmdb`). Карточки, у которых данных ещё нет,
**лениво дозаполняются** при появлении в кадре (`IntersectionObserver` →
`GET /api/films/{id}`; повторные запросы в рамках сессии исключены).
Большая детальная модалка при клике показывает то же + описание.

## Запуск через Docker

### Вариант 1: docker compose (рекомендуется)

```bash
docker compose up -d --build
```

Compose поднимет **6 сервисов**: `db` (PostgreSQL), `jackett`, `catalog`,
`stream`, `auth` и `gateway`. Каждый сервис ждёт готовности зависимостей
(healthcheck), схему БД сервисы создают сами. Веб-интерфейс —
http://localhost:8080.

`./data` (каталог) примонтирован к `catalog`, `./web` (фронтенд) — к
`gateway`, поэтому их можно менять без пересборки образа. После правки
каталога достаточно перезапустить сервисы:

```bash
docker compose restart catalog gateway
```

Логи — по каждому сервису свой контейнер: `docker compose logs -f gateway`
(отдельно `catalog`, `stream`, `auth`, `jackett`, `db`).

Пересоздать БД с нуля: `docker compose down -v && docker compose up -d`.

### Вариант 2: только Dockerfile

Один `Dockerfile` собирает любой сервис через `--build-arg SERVICE`:

```bash
docker build --build-arg SERVICE=gateway -t video-viewer-gateway .
docker build --build-arg SERVICE=catalog -t video-viewer-catalog .
docker build --build-arg SERVICE=stream --build-arg WITH_FFMPEG=1 -t video-viewer-stream .
docker build --build-arg SERVICE=auth -t video-viewer-auth .
```

Пример запуска stream-сервиса:

```bash
docker run -d --name video-viewer-stream -p 42069:42069/udp \
  -e CATALOG_URL=http://host.docker.internal:8081 video-viewer-stream -port 42069
```

### Проброшенные порты

- `8080` — gateway (веб-интерфейс и API);
- `42069/udp` — фиксированный порт торрент-клиента stream (uTP/DHT),
  чтобы пиры могли подключаться снаружи. Если он не нужен, запускайте
  stream с `-port 0` (случайный порт).

## Как добавить видео в каталог

Добавьте запись в `data/catalog.json`:

```json
{
  "id": "my-video",
  "title": "Название видео",
  "magnet": "magnet:?xt=urn:btih:INFO_HASH&dn=name&tr=http://tracker...",
  "poster": "https://example.com/poster.jpg",
  "category": "movies",
  "size": "1.4 GB"
}
```

Поля:

- `id` — уникальный идентификатор, используется в URL стрима;
- `title` — название;
- `magnet` — магнет-ссылка. **Обязательно добавляйте трекеры** (`&tr=...`),
  иначе торрент может не найти пиров;
- `poster` — необязательный URL обложки;
- `category`, `size`, `added_at` — необязательная информация для отображения.

Перезапустите сервер, чтобы каталог обновился. При запуске через Docker:
`docker compose restart`.

## API

| Метод | Путь                | Описание                          |
|-------|---------------------|-----------------------------------|
| GET   | `/api/catalog`      | Каталог (IMDb + магнеты); пагинация `?page=&per_page=` (30), поиск `?q=`, раздел `?section=movie\|series\|tv_movie\|short\|video\|episode\|cartoon\|anime\|other`, жанр `?genre=Drama`, сортировка `?sort=year\|rating\|title` (по умолчанию `year` — дата выпуска; для `popular` не применяется) |
| GET   | `/api/catalog/meta` | Статистика каталога: кол-во по разделам (пересчитывается под `?q=`/`?genre=`) и список жанров |
| GET   | `/api/stream/{id}`  | Видео-поток (поддержка `Range`); `?magnet=` задаёт конкретную магнет-ссылку, `?file=N` — файл (серию) в торренте; если метаданные не пришли за 60 с — `504` |
| GET   | `/api/films/{id}`   | Фильм по IMDb ID; если нет в БД — данные из IMDb |
| GET   | `/api/films/{id}/sources` | Доступные варианты (живой поиск через Jackett): ранжированы по озвучке/качеству/сидам; у каждого `quality`, `audio`, `season` |
| GET   | `/api/films/{id}/files`   | Видеофайлы торрента с сезонами/сериями (селектор серий): `?magnet=` |
| GET   | `/api/films/{id}/tracks`  | Звуковые дорожки файла (ffprobe): `?magnet=&file=`; также `duration` (полная длительность) |
| GET   | `/api/films/{id}/hls.m3u8` | HLS-плейлист (ffmpeg, звук→AAC): `?magnet=&file=&track=&start=` (перемотка) и `&quality=source\|2160\|1080\|720\|480` (понижение качества) |
| GET   | `/api/films/{id}/hls/segments/{name}` | Сегмент HLS: `?magnet=&track=&file=` |
| POST  | `/api/auth/register` | Регистрация: `{"username","password"}` → создаёт аккаунт и сессию (httpOnly-кука) |
| POST  | `/api/auth/login`    | Вход: `{"username","password"}` → новая сессия |
| POST  | `/api/auth/logout`   | Выход (удаляет сессию и куку) |
| GET   | `/api/auth/me`       | Текущий пользователь по куке сессии (`401` без сессии) |
| GET   | `/api/history`       | История просмотра пользователя (с данными фильма: постер, сезон/серия, позиция) |
| POST  | `/api/history/progress` | Сохранить позицию просмотра: `{"film_id","magnet","file","season","episode","position","duration"}` (upsert по user+film+magnet+file) |
| DELETE| `/api/history/{film_id}` | Удалить запись истории (`?magnet=&file=`; без magnet — все записи фильма) |
| DELETE| `/api/history`       | Очистить всю историю пользователя |
| GET   | `/api/health`       | Проверка живости (`ok`)           |

> Авторизация и история работают только при подключённой БД (PostgreSQL);
> без БД эндпоинты `/api/auth/*` и `/api/history` возвращают `503`.
> Пароли хранятся как PBKDF2-хеш со случайной солью (`crypto/pbkdf2`),
> сессии — в таблице `sessions` (токен в httpOnly-куке, TTL 30 дней).

```
│   │   └── parse.go             # разбор качества/озвучки/сезона из заголовка
│   ├── sync/sync.go             # периодическая синхронизация чартов (24ч)
│   ├── torrents/
│   │   ├── manager.go           # торрент-клиент и кэш открытых торрентов
│   │   └── storage_mem.go       # in-memory хранилище (без диска)
│   └── wikidata/                # SPARQL-обогащение карточек (Wikidata)
├── data/catalog.json            # каталог магнет-ссылок
└── web/                         # фронтенд (статика)
```

## Замечания

- Торренты **без сидов** не запустятся — проверяйте, что у магнет-ссылки
  есть активные пиры.
- Всё качается в RAM: большие файлы потребляют много памяти.
  Чтобы ограничить нагрузку, можно уменьшить `defaultReadahead`
  в `internal/streamapi/stream.go` (сейчас 64 MiB).
