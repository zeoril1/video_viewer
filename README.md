# 🎬 Video Viewer

Веб-каталог видео, которые **стримятся по торрент-магнет-ссылкам**: данные качаются (в RAM или во временный дисковый спул) и сразу отдаются плееру по HTTP (Range-запросы); файлы на диске не хранятся — спул удаляется после просмотра. В дисковом спуле место выделяется только под те серии, которые реально качаются (файл создаётся на каждую серию, а не один на весь торрент).

- **Бэкенд:** Go ([anacrolix/torrent](https://github.com/anacrolix/torrent)) — in-memory или временный дисковый спул (`-spool-dir`)
- **Каталог:** PostgreSQL + IMDb/TMDB/Wikidata (чарты, поиск, локализация RU/EN)
- **Фронтенд:** ванильные HTML/CSS/JS, без сборки
- **Стриминг:** `Range` + HLS-транскодинг ffmpeg (звук→AAC, автофолбэк H.265→H.264)

## Архитектура

Браузер ходит только на **gateway** (`:8080`), который раздаёт статику `web/` и проксирует `/api/*` на внутренние сервисы (их порты наружу не публикуются; снаружи также открыт торрент-порт `42069/udp`):

```
Браузер → gateway :8080 ──/api/*──→ catalog :8081  каталог, БД, поиск источников (Jackett)
                                   ├→ stream  :8082  торрент-клиент, стрим, HLS/ffmpeg
                                   ├→ auth    :8083  сессии, история просмотра
                                   └→ iptv    :8084  IPTV: плейлисты, каналы, программа, live
```

Доступ из локальной сети — по `http://<IP-хоста>:8080`; из интернета — через необязательный `caddy` (`https://домен`, профиль `public`), который проксирует на тот же gateway ([подробнее](#-доступ-извне-телевизор-телефон)).

Каталог открывается через `GET /api/catalog`, плеер стримит `GET /api/stream/{id}`: stream добавляет магнет в торрент-клиент, ждёт метаданные и отдаёт данные по мере скачивания. Если в торренте несколько файлов, автоматически берётся самый крупный видеофайл (`.mp4/.mkv/.webm/...`); конкретную серию можно выбрать вручную.

## Быстрый старт

Локально (4 терминала; `go run .` без аргумента выводит список сервисов):

```bash
go mod tidy
go run . gateway   # http://localhost:8080
go run . catalog
go run . stream
go run . auth
go run . iptv     # IPTV: плейлисты, каналы, live-поток
```

Через Docker (поднимает 7 сервисов: db, jackett, catalog, stream, auth, iptv, gateway; восьмой — необязательный `caddy` для доступа из интернета, профиль `public`):

```bash
docker compose up -d --build
```

Порты: gateway `:8080`, catalog `:8081`, stream `:8082`, auth `:8083`, iptv `:8084`. Конфигурация — через `.env` (копия `.env.example`): ключи TMDB (`TMDB_API_KEY` / `TMDB_ACCESS_TOKEN`), статические прокси IMDb (`PROXY_STATIC`, `PROXY_TIMEOUT`, `PROXY_MAX_ATTEMPTS`), dev-пользователь (`DEV_USER` / `DEV_PASSWORD`), `PUBLIC_DOMAIN` (публичный домен для доступа из интернета).

## 🔌 Доступ извне (телевизор, телефон)

Клиенту нужен только **адрес сервера**: и Android-приложение (`video_viewer_android`, тонкая WebView-обёртка), и браузер ходят на `gateway` — он раздаёт интерфейс и проксирует `/api/*`. Фронтенд использует только относительные пути, поэтому работает по любому адресу и порту.

### Локальная сеть (домашний Wi-Fi)

Работает сразу, без настройки: порт `8080` опубликован на всех интерфейсах хоста (`0.0.0.0:8080`).

1. Узнайте IP компьютера с Docker: `ipconfig` (например `192.168.0.10`).
2. Откройте `http://192.168.0.10:8080` — это адрес, который вводится в настройках ТВ-приложения (порт `8080` подставляется сам, если его не писать).
3. Чтобы адрес не «поехал» после перезагрузки роутера, закрепите его за машиной: DHCP-резервирование по MAC или статический IP.

Если брандмауэр Windows включён (PowerShell **от администратора**):

```powershell
New-NetFirewallRule -DisplayName "Video Viewer 8080" -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow -Profile Private
```

### Интернет (проброс портов на роутере)

Публиковать `8080` наружу «как есть» нельзя: пароль от входа пошёл бы открытым текстом. Поэтому в стеке есть необязательный сервис **caddy** (профиль `public`) — обратный прокси с автоматическим HTTPS и сертификатом Let's Encrypt.

1. **Домен**: A-запись на ваш публичный IP. При динамическом IP — бесплатный DuckDNS/No-IP + их клиент обновления (например `vv-home.duckdns.org`).
2. В `.env`: `PUBLIC_DOMAIN=vv-home.duckdns.org`.
3. Запустить: `docker compose --profile public up -d` (обычный `docker compose up -d` caddy не поднимает — локальная сеть работает и без него).
4. **Роутер**: проброс портов `80→80` (проверка Let's Encrypt + редирект) и `443→443` на хост с Docker. Порт `8080` наружу пробрасывать не нужно.
5. Проверить: `https://vv-home.duckdns.org` — сертификат Caddy получит сам (хранится в томе `caddy-data`, поэтому пересоздание контейнера его не теряет).

Что важно знать:

- **Адрес для приложения** — `https://vv-home.duckdns.org` (без порта). Локальный и публичный адреса работают с одним сервером одновременно: Caddy передаёт `X-Forwarded-Proto: https`, и кука сессии автоматически получает флаг `Secure`; при локальном HTTP флага нет (иначе вход по LAN не работал бы).
- Сессия/история привязаны к origin: вход по локальному адресу не действует на публичном домене — там нужно войти отдельно.
- **Перед открытием доступа наружу смените пароль** и уберите `DEV_USER`/`DEV_PASSWORD` из `.env`, если они не нужны: двухфакторной аутентификации нет, а админ-эндпоинты (`/api/admin/*`, управление плейлистами IPTV) доступны роли admin.
- `/api/debug/*` наружу не проксируется (диагностика доступна только во внутренней сети compose).
- Наружу также открыт торрент-порт `42069/udp` — трафик раздачи идёт с вашего домашнего канала (нужен хотя бы небольшой исходящий).
- Не хочется «светить» домашний IP — тот же `gateway` можно выставить через туннель (Cloudflare Tunnel) вместо проброса портов.

## 📺 IPTV

Страница **«📺 IPTV»** (отдельная вкладка, `/iptv.html`) открывает список каналов, плеер и телепрограмму («сейчас/далее» и список передач канала). Каналы берутся из плейлистов, которые добавляет админ (⚙ рядом с заголовком):

- **M3U-ссылка** любого провайдера (например, публичный бесплатный плейлист `https://iptv-org.github.io/iptv/languages/rus.m3u` — ~620 каналов РФ; там есть `tvg-logo`, группы и заголовки `http-user-agent`/`http-referrer`, которые нужны части каналов). Каналы о природе лежат в тематических списках iptv-org: `https://iptv-org.github.io/iptv/categories/outdoor.m3u` (73 канала: Love Nature, МОЯ ПЛАНЕТА, Дикая охота/рыбалка, Animal Kingdom), `…/relax.m3u` (9: Better Life Nature, WildEarth) и `…/documentary.m3u` (249: BBC Earth, Discovery, наука) — природа и документалистика. Полный список категорий: `https://iptv-org.github.io/api/categories.json`.
- **Xtream Codes** (адрес панели + логин/пароль) — каналы и программа забираются через `player_api.php`.
- **EPG (XMLTV)** — необязательная ссылка на телепрограмму; для РФ проверен `https://www.teleguide.info/download/new3/xmltv.xml.gz` (~130 каналов и ~10 тыс. передач сопоставляются по названию). Сопоставление идёт по порядку: точный `tvg-id` → название канала → нормализованный id (без домена `.ru`, пометки `@SD`/`@HD` и качества). Бесплатные файлы `open-epg.com` для РФ — демо из 10 каналов, они не подходят.

Клиент **никогда не видит адрес потока и логины провайдера** — плеер получает только `id` канала, а поток тянет сервис iptv:

- если канал уже отдаётся как **HLS**, сервис проксирует плейлист и все сегменты (включая вложенные плейлисты, `#EXT-X-KEY`/`#EXT-X-MAP`), подменяя ссылки на свои `/api/iptv/seg/{token}` — так не утекают креды и не мешает CORS;
- если канал отдаётся **MPEG-TS** (или звук провайдера не декодируется браузером — AC-3/E-AC-3), сервис поднимает live-сессию ffmpeg: видео копируется, звук перекодируется в AAC, отдаются fMP4-сегменты по 4 с из `/api/iptv/live/{id}/{sid}/{name}`. Явно запросить этот режим можно параметром `?remux=1` — плеер делает это сам, если hls.js упирается в несовместимый звук. Неактивные сессии гасятся сами (по умолчанию через 90 с без запросов, не больше 8 одновременно — флаги `IPTV_MAX_SESSIONS`, `IPTV_SESSION_IDLE`). Сегменты отдаются с `temp_file` (файл появляется целиком), а в ссылке участвует id сессии — после перезапуска ffmpeg старый плейлист перестаёт работать, и плеер перезапрашивает новый вместо склейки кусков разных запусков.

В интерфейсе каналов есть поиск, чипы групп (составные группы iptv-org вроде `Comedy;Movies` разбиваются на части, названия категорий показываются по-русски — «Природа и отдых», «Документальные», «Кино»; фильтрация при этом идёт по исходному имени из плейлиста) и «сейчас/далее»; пульт ТВ-режима работает как обычно. Заголовки `http-user-agent`/`http-referrer` из плейлиста и общие UA/Referer плейлиста подставляются при запросе потока — без них многие российские каналы не отдают видео.

Плейлисты обновляются фоном (`IPTV_SYNC_INTERVAL`, по умолчанию 6 ч) и вручную («Обновить» в админке). Есть экспорт каналов в один M3U: `GET /api/iptv/export.m3u` — можно вставить в VLC на телефоне/ТВ. Для iptv-org-каналов программа доступна там, где нашлось сопоставление: остальные каналы просто играются без «сейчас/далее».

## Jackett (поиск раздач)

Весь поиск источников идёт **только через Jackett** (Torznab): RuTracker и другие трекеры закрыты Cloudflare/антиботом, а Jackett сам хранит доступы, решает капчу при настройке и обходит защиту. Jackett поднимается вместе с compose (UI `http://localhost:9117`, конфиг в `./jackett/`). Настройка вручную:

1. Добавьте индексер **RuTracker.org** в веб-интерфейсе Jackett (логин/пароль + капча).
2. Укажите в `.env` `JACKETT_API_KEY` (поле `"APIKey"` в `./jackett/Jackett/ServerConfig.json`) и при необходимости `JACKETT_INDEXER` (по умолчанию `rutracker-ru`; неверный ID → `Indexer is not configured`).
3. Перезапустите `docker compose up -d`.

Поиск асинхронный: `GET /api/films/{id}/sources` мгновенно возвращает результат из БД (или статус `"searching"` — фронтенд опрашивает каждые ~4 с, поиск до ~3 мин). Из заголовков раздач парсятся качество/озвучка/сезон, варианты ранжируются «озвучка → качество → сиды». Раздачи сохраняются в PostgreSQL (таблица `sources`; ключ — `info_hash`, чтобы не плодить дубли от сессионных токенов магнитов).

У сериалов переводы (озвучки) сезона определяются по заголовкам раздач, поэтому сохраняются и **раздачи без сидов**, если в заголовке названа студия озвучки (LostFilm, TVShows, Novamedia, Jaskier, Amedia, Gears Media…) или это полный сборник: часто такие раздачи — единственный источник перевода, и без них в интерфейсе остаётся один перевод (пример: 2 сезон «Хорошего доктора» — TVShows/Novamedia/Jaskier есть только с 0 сидов). Мусор без студии отбрасывается. Фронтенд тоже их не выбрасывает: они видны как чипы «Озвучки», но автопросмотр (серия, кнопка «▶ Смотреть», проба серий) всегда предпочитает раздачи с сидами. Поиск по сезону идёт шире (20 раздач на индексера, общий запрос по названию — 30), но число «докачиваний» `.torrent` из Jackett ограничено 8 на запрос, чтобы не бить по приватным трекерам; у индексаторов с готовым `magneturl` (RuTracker, RuTor) лишних запросов нет вовсе.

## Возможности

- **Пропуск заставок, пересказов и титров:** главы видео и готовые отметки TheIntroDB, отдельные режимы кнопки/автопропуска, личные исправления границ для конкретного файла. Внешнюю разметку нужно подтвердить перед автопропуском; сцены между блоками титров сохраняются. [Настройки и подробности](docs/skip-segments.md).
- **Сериалы:** источники группируются по сезонам; серия выбирается через `GET /api/films/{id}/files` и параметр `file` (индекс в торренте). Сезоны приводятся к нумерации **TMDB** (источник истины: у «Реальных пацанов» 10 сезонов и 291 серия). У трекеров своя, более дробная нарезка (те же серии, но 14 «сезонов»), поэтому раздачи раскладываются по сезонам TMDB по году выпуска из заголовка (`[S14] (2023)` → сезон 10 «Прощальный сезон»), а полные сборники со сквозной нумерацией файлов («001 seriya» … «291 seriya») — по структуре сезонов из TMDB; для этого клиент передаёт в `/files` заголовок раздачи и `tmdb`-id. Без ключей TMDB работает прежний разбор по именам файлов.
- **Звук и дорожки (HLS):** чтобы играли AC3/DTS/EAC3 (браузер их не декодирует), видео отдаётся через HLS — ffmpeg копирует видео (`-c:v copy`) и перекодирует звук в AAC. `/api/films/{id}/tracks` — список дорожек и полная длительность (ffprobe); `/api/films/{id}/hls.m3u8` — плейлист с выбором `track`, перемоткой `start` (с рестартом ffmpeg) и понижением качества `quality=source|2160|1080|720|480`. По умолчанию используется `source`, в том числе при смене серии. Автоматического переключения на 1080p нет; для несовместимого с браузером кодека можно вручную выбрать качество с перекодированием в H.264.
- **Плеер:** свои контролы — полная длительность, полоса уже переданного (`video.buffered`), перемотка в любое место. Медленный старт (ожидание пиров/метаданных) — норма, таймауты hls.js увеличены.
- **Память/диск:** по умолчанию стрим в RAM; при `-spool-dir`/`STREAM_DATA_DIR` скачанные куски пишутся во временные файлы спула на диске сервера (данные — в OS page cache, а не в heap) и удаляются после просмотра. Спул — **по одному файлу на серию/файл торрента**: место на диске выделяется только под то, что реально качается (для одной серии сезон-пака — размер серии, а не всего пака). При закрытии плеера торрент без активных читателей выгружается через `DropGrace` (~90 с), затем `runtime.GC()` + `debug.FreeOSMemory()`. Упреждающее скачивание вперёд от позиции — `-readahead` (по умолчанию 64 MiB; при спуле не ест RAM). Диагностика: `GET /api/debug/mem` (в `torrents` видны `spool_files`/`spool_bytes`).
- **Логи:** каждый HTTP-запрос, открытие торрента, работа ffprobe/ffmpeg (включая stderr `ffmpeg: ...`). Панель логов плеера — кнопка 🛠 или параметр `?debug`.

## Каталог и источники данных

- **IMDb:** топ-250 и «популярные» — скрапер официальных страниц с фолбэком на JSON-зеркало (`-imdb-top250-url`); on-demand загрузка фильмов по ID. RU-локализация выполняется фоном через Wikidata → русскую Википедию.
- **TMDB** (ключами в env включаются чарты и внешний поиск): «популярные», «топ-250», поиск; дедуп с IMDb по `imdb_id`, записи без IMDb-ссылки не добавляются. Поиск идёт через `/search/multi`, то есть находит и фильмы, и сериалы (для сериалов берутся поля `name`/`first_air_date`, IMDb-ссылка — из `/tv/{id}/external_ids`; люди из выдачи отбрасываются).
- **Сезоны и серии:** структура сериалов из TMDB сохраняется в PostgreSQL (`series_seasons`, `series_episodes`). Список сезонов и число серий читаются независимо от поиска раздач; названия и даты серий загружаются только для выбранного сезона. Кэш обновляется в фоне раз в сутки, прежние данные остаются доступными при ошибке TMDB. Таблицы создаются при запуске catalog. При наличии данных TMDB открытие сетки не запрашивает файлы торрентов; файлы проверяются при выборе серии. Без TMDB сохраняется резервное определение серий по раздачам.
- **Wikidata** (без ключей): обогащение карточек — длительность, страна, режиссёр, актёры (по `P345`); результат кэшируется в БД.
- **Имена людей на языке сайта:** TMDB отдаёт режиссёра/актёров на языке запроса, поэтому пары «оригинал → русский» складываются в отдельную таблицу `person_names` (`internal/db/people.go`), а API отдаёт их полями `director_ru`/`actors_ru` (интерфейс на английском показывает исходное написание из `films.director`/`actors`). Пары забираются по `tmdb_id` фильма: фоном при открытии карточки (поле `people_pending` в ответе просит клиента переспросить её через пару секунд) и разово по всему каталогу — `go run ./cmd/backfill -people` (нужны `DATABASE_URL` и `TMDB_API_KEY`/`TMDB_ACCESS_TOKEN`).
- Кинопоиск **отключён** (лимиты токена + антибот), пакет `internal/kinopoisk/` удалён. Рейтинг в карточке: IMDb → TMDB.

Флаги catalog: `-dsn` (env `DATABASE_URL`), `-imdb-interval` (синхронизация чартов, `24h`), `-imdb-scrape`, `-jackett-url/-api-key/-indexer`, `-proxy-static/-timeout/-max-attempts`, `-localize-interval`, `-localize-workers`, `-tmdb-url`.

Каталог фильмов наполняется из IMDb/TMDB, источники для просмотра находятся через Jackett.

Поиск источников учитывает каждый трекер из списка `JACKETT_INDEXER` отдельно. Если для фильма не найдено подходящих названий, трекер пропускается на 24 часа; другие фильмы и трекеры продолжают проверяться. Перед этим пробуется исходное название, если оно отличается от русского. Ошибки не считаются пустой выдачей. Состояние пропусков хранится в памяти (до 4096 пар), сбрасывается при перезапуске catalog. Для отдельного учёта указывайте ID трекеров через запятую: `all` остаётся агрегированным поиском без отключения отдельных трекеров. Частично успешный поиск завершается и обновляется через обычные 20 минут, сохраняя прежний кэш при ошибках отдельных трекеров.

Статика `web/` включена в образ gateway. При развёртывании через Portainer Git Stack изменения фронтенда требуют пересборки и переразвёртывания gateway; пустой bind mount поверх `/app/web` добавлять не нужно.

Обложки TMDB/IMDb браузер запрашивает через `/api/poster?url=…` на домене сайта. Gateway передаёт запрос в catalog, который использует `HTTP_PROXY`/`HTTPS_PROXY` (на домашнем сервере — `http://gluetun:8888`). Исходные `poster_url` в БД и истории не меняются. Разрешены только HTTPS-адреса CDN TMDB/IMDb, включая проверку перенаправлений. Максимальный размер изображения — 4 МиБ, до 8 одновременных загрузок; успешные ответы кэшируются в памяти до 24 часов (32 МиБ, 512 записей). Ошибки возвращаются с `no-store`. Для применения через Portainer Git Stack нужно обновить код, пересобрать и переразвернуть catalog и gateway; простой Restart не обновляет образы. Существующий `wget -Y off` в healthcheck catalog сохраняется.

В админке список пустых полей выводится целиком. Рейтинг IMDb не обязателен; рейтинг TMDB не считается пропуском до даты выхода (дата сравнивается по Москве, неизвестная дата не считается будущей). Проверяются тип, русское название и описание, жанры, постер, TMDB ID и рейтинг TMDB вышедших фильмов. «Обновить все» обрабатывает снимок очереди в 4 потока; повторный массовый запуск блокируется. Ошибки и записи с оставшимися пустыми полями попадают в «Не удалось обновить» на 7 дней, с причиной и сроком возврата. Состояние хранится в PostgreSQL и переживает перезапуск. В отдельной таблице можно повторить обновление вручную или вернуть запись в очередь раньше срока. Новая таблица создаётся автоматически при запуске catalog.

## API (основное)

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/api/catalog` | Каталог: `?q=&page=&per_page=&section=&genre=&sort=` |
| GET | `/api/catalog/meta` | Статистика по разделам и список жанров |
| GET | `/api/stream/{id}` | Видеопоток (Range); `?magnet=` (конкретная раздача), `?file=N` (серия) |
| GET | `/api/films/{id}` | Фильм по IMDb ID (on-demand из IMDb/TMDB) |
| GET | `/api/films/{id}/sources` | Варианты раздач (живой поиск через Jackett) |
| GET | `/api/films/{id}/seasons` | Сезоны и число серий из локального кэша TMDB; `status`, `stale` |
| GET | `/api/films/{id}/seasons/{season}` | Названия и даты серий выбранного сезона из локального кэша TMDB |
| GET | `/api/films/{id}/files` | Видеофайлы торрента с сезонами/сериями |
| GET | `/api/films/{id}/tracks` | Звуковые дорожки + длительность (ffprobe) |
| GET | `/api/films/{id}/hls.m3u8` | HLS-плейлист: `?track=&file=&start=&quality=`; сегменты — `/hls/segments/{name}` |
| POST | `/api/auth/register`, `/api/auth/login`, `/api/auth/logout` | Регистрация/вход/выход (httpOnly-кука) |
| GET | `/api/auth/me` | Текущий пользователь по сессии |
| GET | `/api/history`; POST `/api/history/progress`; DELETE `/api/history[/{film_id}]` | История просмотра (позиция/сезон/серия) |
| GET | `/api/health` | Живость сервиса |
| GET | `/api/iptv/channels` | Каналы: `?playlist=&group=&q=&limit=&offset=` (без адресов провайдера) |
| GET | `/api/iptv/groups` | Группы каналов (чипы в интерфейсе) |
| GET | `/api/iptv/epg` | Программа канала: `?channel={id}&limit=` (плюс «сейчас/далее» для списка) |
| GET | `/api/iptv/play/{id}.m3u8` | HLS-плейлист канала (прокси; `?remux=1` — принудительная перепаковка) |
| GET | `/api/iptv/seg/{token}`, `/api/iptv/live/{id}/{sid}/{name}` | Сегменты потока (прокси и ffmpeg-сессия) |
| GET | `/api/iptv/export.m3u` | Все каналы одним M3U-плейлистом (для VLC/ТВ) |
| POST/DELETE | `/api/iptv/playlists[/{id}]`, `POST /api/iptv/playlists/{id}/sync`, `POST /api/iptv/epg/sync` | Управление плейлистами и синхронизацией (только админ) |

Авторизация и история требуют PostgreSQL (без БД — `503`). Пароли хранятся как PBKDF2-хеш с солью, сессии — в таблице `sessions` (токен в httpOnly-куке, TTL 30 дней). Фильмы из IMDb магнетов не содержат: доступен просмотр карточки, стрим появляется после выбора раздачи в источниках.

## Структура

```
main.go              # диспетчер: go run . <gateway|catalog|stream|auth|iptv>
cmd/                 # точки входа микросервисов (gateway, catalog, stream, auth, iptv; backfill — разовая утилита)
internal/
  catalogapi/        # HTTP-хендлеры catalog (каталог, фильмы, источники)
  streamapi/         # HTTP-хендлеры stream (стрим, файлы, HLS)
  authapi/           # HTTP-хендлеры auth (сессии, история)
  iptvapi/           # HTTP-хендлеры iptv (каналы, программа, live-прокси/ffmpeg)
  gatewayapi/        # reverse-proxy + health
  iptv/              # разбор M3U/M3U8, Xtream Codes и XMLTV
  catalog/ db/ httpx/                 # торрент-запись, PostgreSQL, HTTP-утилиты
  imdb/ tmdb/ wikidata/ sync/ magnet/  # источники данных и фоновая синхронизация
  torrents/ proxy/                     # in-memory торрент-клиент, пул HTTP-прокси
web/                 # фронтенд (статика, отдельные страницы)
```

### Страницы фронтенда

Сайт — набор обычных страниц (не одностраничное приложение): состояние передаётся
через адрес и `sessionStorage`, каждый переход — обычная ссылка (работает «назад»
в браузере и кнопка Back на ТВ-пульте).

| Страница | Что делает |
| --- | --- |
| `/` (`index.html`) | Каталог: разделы/жанры/сортировка, поиск, «Продолжить просмотр», бесконечная прокрутка. Карточка — ссылка на страницу фильма |
| `/film.html?id={imdb}` | Карточка фильма/сериала: описание, сезоны, озвучки, сетка серий. У **сериалов** плеер здесь же (выбрал сезон/озвучку/серию — играет на месте, без отдельной страницы); отсюда же авто-переход к следующей серии (`?season=&ep=&voice=&autoplay=1`) |
| `/watch.html?id=&magnet=&file=` | Просмотр **фильмов** (и старые/внешние ссылки на сериал): плеер (HLS, качество, дорожки, субтитры), серии текущей раздачи, сохранение прогресса |
| `/iptv.html` | IPTV: каналы, поиск и группы, плеер канала, телепрограмма, плейлисты (админ) |
| `/login.html` | Вход/регистрация; после входа возврат на `?next=` |
| `/admin.html` | Админ-панель каталога |

Скрипты: `shared.js` (язык, авторизация, история, утилиты — на всех страницах),
`series.js` (логика сезонов TMDB/озвучек/раздач), `player.js` (плеер: HLS, дорожки,
субтитры, качество, прогресс — общий для карточки сериала и страницы просмотра фильма),
`catalog.js`, `film.js`, `watch.js`, `iptv.js`, `login.js`, `admin.js` и `tv.js`
(D-pad ТВ-режима).

## Замечания

- Торрент **без сидов** не запустится — проверяйте наличие пиров у магнет-ссылки.
- По умолчанию всё стримится в RAM. Чтобы снизить нагрузку на память, включите **дисковый спул**: флаг `-spool-dir <каталог>` у stream (или `STREAM_DATA_DIR`, в compose включён volume `/app/cache`). Спул хранит по одному файлу на серию/файл торрента и удаляет их после просмотра, поэтому место на диске занимает только то, что реально качается (сезон-пак не разворачивается целиком). Упреждающее скачивание — `-readahead <байт>` (`defaultReadahead` в `internal/streamapi/stream.go`, 64 MiB).
- Для HLS нужен ffmpeg/ffprobe (есть в `Dockerfile`); без него фронтенд откатывается на прямой стрим без транскодинга.

### Trusted reverse proxy

Gateway overwrites `X-Video-Viewer-Client-IP` before forwarding requests to
internal services. Auth uses this address for per-client login limits; keep
its port private. Direct connections ignore client-supplied forwarding headers.
For an upstream proxy set `TRUSTED_PROXY` to its hostname or IP. Gateway accepts
the last `X-Forwarded-For` address only when the connection comes from that proxy;
the proxy must append or overwrite this address using its actual client address.
Docker Compose defaults to `caddy`. For a different proxy, change this setting;
for direct-only access leave it empty when starting gateway outside Compose.

HLS requests from the web player carry a random `session` identifier per tab.
Custom clients should pass their own random identifier on the initial playlist
and stop requests; generated media, subtitle and segment URLs preserve it.
Legacy clients without this parameter retain the shared session behavior.
